## 每一天都采用五步教学法：
1. 课程（Learn）
   
   学习当天的技术知识、核心概念、架构原理。
2. 编码（Code）
   
   跟着实战任务写 Python 代码，运行 Agent 或测试工具。
3. 测试（Test）
   
   自己设计测试用例，执行测试，观察异常和缺陷。
4. 分析（Analyze）
   
   分析失败原因，理解模型行为、工具调用及业务逻辑。
5. 复盘（Review）
   
   整理技术笔记、测试报告、代码及当天学习成果。

## 三、我们以后每天具体怎么学习？

这里是我认为最需要调整的地方。

测试用例设计只是学习手段，不是整个课程的核心目标。

以后每一天都围绕一个具体技术能力展开，采用以下教学结构：

| 环节        | 学习内容               | 目的     |
| --------- | ------------------ | ------ |
| 1. 原理     | 学习当天技术的工作机制        | 理解技术   |
| 2. 架构     | 分析它在 Agent 中的位置和作用 | 理解整体链路 |
| 3. 编码     | Python 实现或调用相关技术   | 掌握技术   |
| 4. 测试     | 使用 Pytest 验证关键行为   | 掌握测试方法 |
| 5. 分析     | 分析异常、缺陷和 Trace     | 培养定位能力 |
| 6. Review | 检查代码、技术理解和测试质量     | 验收学习成果 |

举个例子：

Tool Calling 不应该只学习如何写 5 个测试用例。

真正应该掌握的是：

- LLM 为什么会产生 Tool Call？
- Function Calling 和普通文本输出有什么区别？
- Tool Schema 是如何定义和传递的？
- Agent 如何解析工具调用参数？
- Agent 如何执行工具并处理返回结果？
- 如何使用 FakeLLM 模拟工具调用？
- 如何使用 Mock 验证真实工具执行？
- 如何测试工具调用异常、参数错误和执行边界？

测试用例是用来验证这些技术理解和实现的，而不是课程本身的终点。

# **四、最重要的调整：改变每天的教学方式**

我认为这比修改天数更重要。

以后每个学习模块统一采用以下教学方式：

## **新的学习闭环**

1. **1. 原理与架构**

   讲清楚技术原理、执行机制、关键组件之间的关系。

   不只是告诉你是什么，还要解释为什么这样设计。
2. **2. 真实项目实践**

   使用现有 `ai-agent-testing` 项目，以电商支付 Agent 为主线，理解和实现相关功能。
3. **3. 测试设计**

   从测试工程师角度分析风险、测试边界、预期行为和异常场景。

   只保留高价值测试，不以 Case 数量作为学习成果。
4. **4. Python + Pytest 实践**

   重点是你能够自己编写、理解和维护测试代码，而不是依赖 AI 生成完整代码。
5. **5. 严格评审**

   我会检查代码质量、测试思路、技术理解和缺陷分析，给出评分及修改意见。
6. **6. 面试能力转化**

   每个重要知识模块，都要能够用面试语言解释架构、测试思路和实际问题。

## **五、以后明确禁止的学习方式**

以下几条作为课程约束：

| 不再采用           | 改为           |
| -------------- | ------------ |
| 为了完成天数而拆分知识点   | 根据实际能力确定学习内容 |
| 为了覆盖率增加大量 Case | 关注核心风险与高价值场景 |
| 反复考察已经掌握的概念    | 通过综合实践验证掌握程度 |
| 只做选择题和概念问答     | 增加架构分析、代码实践  |
| 为了学习而堆砌代码      | 理解机制后再独立实现   |
| 每天必须完成新知识      | 掌握就通过，不掌握就补齐 |

另外，我会特别注意：**不能把 Agent 测试学习变成单纯的 Pytest 练习。**

我们真正需要建立的是 AI Agent 测试能力，包括模型行为、非确定性、工具执行、上下文管理、检索质量、执行链路和质量评估。
