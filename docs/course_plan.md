## 每一天都采用五步教学法：
1. 课程（Learn）
   
   学习当天的技术知识、核心概念、架构原理。
2. 编码（Code）
   
   跟着实战任务写 Python 代码，运行 Agent 或测试工具。
3. 测试（Test）
   
   自己设计测试用例，执行测试，观察异常和缺陷。
4. 分析（Analyze）
   
   分析失败原因，理解模型行为、工具调用及业务逻辑。
5. 复盘（Review）
   
   整理技术笔记、测试报告、代码及当天学习成果。

## 三、我们以后每天具体怎么学习？

这里是我认为最需要调整的地方。

测试用例设计只是学习手段，不是整个课程的核心目标。

以后每一天都围绕一个具体技术能力展开，采用以下教学结构：

| 环节        | 学习内容               | 目的     |
| --------- | ------------------ | ------ |
| 1. 原理     | 学习当天技术的工作机制        | 理解技术   |
| 2. 架构     | 分析它在 Agent 中的位置和作用 | 理解整体链路 |
| 3. 编码     | Python 实现或调用相关技术   | 掌握技术   |
| 4. 测试     | 使用 Pytest 验证关键行为   | 掌握测试方法 |
| 5. 分析     | 分析异常、缺陷和 Trace     | 培养定位能力 |
| 6. Review | 检查代码、技术理解和测试质量     | 验收学习成果 |

举个例子：

Tool Calling 不应该只学习如何写 5 个测试用例。

真正应该掌握的是：

- LLM 为什么会产生 Tool Call？
- Function Calling 和普通文本输出有什么区别？
- Tool Schema 是如何定义和传递的？
- Agent 如何解析工具调用参数？
- Agent 如何执行工具并处理返回结果？
- 如何使用 FakeLLM 模拟工具调用？
- 如何使用 Mock 验证真实工具执行？
- 如何测试工具调用异常、参数错误和执行边界？

测试用例是用来验证这些技术理解和实现的，而不是课程本身的终点。

## 五、我会调整后续教学的验收标准

以后不再出现 pytest 全部通过，就认为当天学习完成的情况。

每天至少从以下四个维度验收：

1. 理论理解： 能否独立解释技术原理和执行机制？
2. 编码能力： 能否独立编写或修改核心代码？
3. 测试能力： 能否用合适的测试技术验证真实问题？
4. 问题分析： 能否发现实现缺陷、解释原因并定位问题？

代码评审会特别关注：代码是不是自己真正理解的、测试是否能发现缺陷、Mock 是否使用合理、断言是否有意义。

最终确认：我们继续采用原来的 16 周课程体系，分成 30 天面试冲刺 + 50 天项目能力提升。 不再把学习重心局限在 Cases 设计上，而是以 Agent 技术原理、Python 实现、测试技术和工程能力为主线。
