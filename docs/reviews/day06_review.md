### 重点修正 1：FakeLLM

面试推荐回答：

> FakeLLM 是一个测试替身，用来模拟真实 LLM。它可以按照预设顺序返回固定响应，并记录调用次数和请求上下文。这样可以避免真实 LLM 的不确定性，使 Agent 测试结果稳定、可重复。

### 重点修正 2：Mock 和 Mock(wraps=...)

你的理解正确。

- `Mock()`：模拟对象或方法，不会自动执行原方法。
- `Mock(wraps=原方法)`：调用时执行原方法，同时记录调用次数、参数等信息。

### 重点修正 3：max_steps

推荐回答：

> Agent 不能只限制 LLM 请求轮数，因为一次 LLM 响应可能包含多个 Tool Calls。因此，需要在每次工具执行前检查累计调用次数，超过最大限制时立即终止，避免工具被过量执行。

### 重点修正 4：工具异常

这里需要特别加强。

不能只检查 `state.final_response`，还应该检查：

1. `state.status == "failed"`：Agent 确实进入失败状态。
2. `state.final_response`：向用户返回正确的错误信息。
3. `state.trace`：记录工具执行异常，便于问题排查。
4. 异常发生后是否停止后续执行。

这才是比较完整的异常测试。
