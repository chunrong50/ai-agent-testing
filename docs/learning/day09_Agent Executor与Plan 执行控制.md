## 二、先理解 Agent Executor 的工作机制

我们继续使用电商退款场景。

用户提出：

> 帮我查询订单 A10086，如果符合退款条件，就申请退款，并通知用户退款结果。

Agent 经过 Day 8 的 Planning，生成如下 Plan：

Refund Plan

1. Step 1：query_order

   completed

   查询订单信息。
2. Step 2：permission_check

   completed

   检查用户是否有权限操作该订单。
3. Step 3：execute_refund

   pending

   执行退款。
4. Step 4：send_notification

   pending

   通知用户退款结果。

Executor 拿到 Plan 后，开始执行。

它不是简单地从 Step 1 一直循环到 Step 4，而是需要考虑：

1. 当前 Step 是否已经完成？
2. 当前 Step 的前置依赖是否满足？
3. 执行成功后，是否更新为 completed？
4. 执行失败后，是否应该继续？
5. 如果程序发生异常，如何保存当前执行状态？

这就是 Day 9 的核心。

## 三、Executor 的执行逻辑

我们先看一个简化执行流程：

Executor 接收 Plan

检查 Step 状态及依赖

执行当前 Step

执行成功

更新 completed

检查下一个 Step

执行失败

更新 failed

进入失败处理逻辑

继续执行 / 重试 / 终止 / 恢复

这里有一个非常重要的设计原则：

Executor 负责执行和记录结果，不应该把所有业务决策都写死在 Executor 中。

例如：

- Tool 执行成功：更新 Step 状态。
- Tool 暂时不可用：可以考虑重试。
- 订单不满足退款条件：属于业务失败，不应该盲目重试。
- 权限校验失败：应该终止退款流程。

要区分技术异常和业务失败。

## 四、必须掌握的 Step 状态变化

先掌握以下四种状态：

| 状态        | 含义   |
| --------- | ---- |
| pending   | 等待执行 |
| running   | 正在执行 |
| completed | 执行成功 |
| failed    | 执行失败 |

例如：

正常执行

pending

running

completed

执行失败

pending

running

failed

这里有两个需要特别注意的问题。

问题 1：执行成功后，必须更新状态。

如果 Step 3 已经成功退款，但状态没有更新为 completed，那么 Agent 恢复执行时可能再次调用退款工具。

对于支付、退款这种有交易副作用的操作，重复执行可能造成严重问题。

问题 2：业务失败不能简单当成技术异常。

例如：

- 网络超时：可能适合重试。
- 退款金额不一致：不应该重试。
- 无权操作订单：应该终止。

这两类问题在测试中需要区别验证。

## 六、Day 9 的面试知识点

你需要能够回答下面这个问题：

问题：Agent 在执行一个多步骤任务时，如果第三个 Step 执行失败，应该如何处理？

一个比较完整的回答应该包含：

1. 将第三个 Step 标记为 failed，并记录失败原因。
2. 检查失败类型，区分技术异常和业务失败。
3. 如果属于可恢复的技术异常，可以根据重试策略处理。
4. 如果属于业务校验失败，则停止依赖该步骤的后续操作。
5. 保留之前已经完成的 Step 状态，避免重复执行。
6. 恢复执行时，从符合执行条件的失败步骤继续，而不是无条件从头开始。

注意：恢复执行不代表一定从第三步直接开始，还需要重新检查依赖关系和业务状态。

今天先不急着增加代码。我们先检查你是否真正理解 Executor 的执行机制。

请回答下面三个问题：

问题 1：已完成步骤如何处理？

假设：

- Step 1：查询订单，completed
- Step 2：权限检查，completed
- Step 3：执行退款，pending
- Step 4：发送通知，pending

Agent 因程序异常退出后重新启动。

Executor 应该从哪个 Step 开始处理？为什么？

问题 2：技术异常如何处理？

Step 3 `execute_refund` 调用退款工具时，发生网络超时。

此时你认为应该：

A. 直接将整个 Plan 标记为 failed。

B. 将 Step 3 标记为 failed，允许后续恢复处理。

C. 立即重新执行退款，不做其他检查。

请说明理由。

问题 3：业务失败如何处理？

Step 3 执行退款时，退款工具返回：

```
{    "success": False,    "error_code": "REFUND_AMOUNT_MISMATCH",    "message": "退款金额与订单金额不一致"}
```

此时：

- Step 3 应该是什么状态？
- Step 4 是否应该执行？
- 是否应该自动重试？
