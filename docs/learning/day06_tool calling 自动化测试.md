## 一、重新确定 Day 6 的定位

## Day 6｜Tool Calling 自动化测试

第一阶段面试必备

核心目标： 能够使用 Pytest 自动验证 Agent 是否正确选择工具、生成参数、处理异常，以及按预期顺序调用多个工具。

今天不要求你实现一个完整的生产级 Agent，而是要具备独立设计和编写 Tool Calling 自动化测试的能力。

Day 6 应该覆盖以下五个知识点：

| 知识点     | 面试重要性 | 具体要求                   |
| ------- | ----- | ---------------------- |
| 工具选择测试  | 高     | 是否选择正确工具，是否误调用工具       |
| 参数生成测试  | 高     | 工具参数是否正确，是否存在缺失或非法参数   |
| 多工具调用测试 | 高     | 工具调用顺序、参数传递是否正确        |
| 异常处理测试  | 高     | 工具异常后是否正确处理，是否错误返回成功   |
| 调用循环控制  | 中高    | 是否避免无限调用，是否达到最大调用次数后终止 |

这五项比单独学习复杂的 Agent 执行机制更符合你当前的面试目标。

## 二、调整后的 Day 6 学习内容

建议采用下面的结构，控制在一天可以完成的范围内。

### 1. 工具选择测试

场景：用户要求查询订单 A10086。

测试重点：

- Agent 是否选择 `query_order`。
- 是否错误选择 `execute_refund`。
- 是否调用了不在允许列表中的工具。

### 2. 工具参数测试

场景：用户要求查询订单 A10086。

测试重点：

- 是否正确生成 `order_id=A10086`。
- 是否出现参数缺失。
- 是否出现错误参数类型。

### 3. 多工具调用测试

场景：用户要求退还订单 A10086。

预期调用顺序：

query_order

查询订单信息

check_permission

检查用户权限

execute_refund

执行退款

测试重点：

- 工具是否按正确顺序执行。
- 前一个工具的结果是否正确传递给后一个工具。
- 权限检查失败时，是否阻止退款。

### 4. 异常处理测试

场景：`query_order` 或 `execute_refund` 执行时抛出异常。

测试重点：

- Agent 是否崩溃。
- 是否正确记录失败结果。
- 是否错误返回操作成功。
- 订单查询失败后是否仍然继续退款。

### 5. Tool Calling Loop 控制

场景：FakeLLM 连续要求 Agent 调用工具。

测试重点：

- 是否设置最大工具调用次数。
- 超过上限是否终止。
- 是否避免无限循环。

## 三、Day 6 最终作业：5 个核心测试用例

我建议将作业控制在 5 个测试，不再增加大量边界用例。

| 用例   | 测试内容         | 核心考察能力    |
| ---- | ------------ | --------- |
| TC01 | 正确选择工具和参数    | 工具选择、参数生成 |
| TC02 | 多工具调用顺序正确    | 多工具协作     |
| TC03 | 权限检查失败，不执行退款 | 流程控制、安全性  |
| TC04 | Tool 执行异常    | 异常处理      |
| TC05 | 连续调用超过最大次数   | Loop 控制   |

注意：TC01 可以同时检查工具名称和参数，因此不需要再拆成两个独立测试。这样能减少重复代码，同时覆盖核心能力。
